# llama.cpp для Windows — Установка, Обновление и Удаление

Комплект скриптов для развёртывания и обслуживания [llama.cpp](https://github.com/ggml-org/llama.cpp) на Windows в виде службы через [NSSM](https://nssm.cc). Сервер запускается как `llama-server.exe` в режиме **Router** (динамическая загрузка моделей по запросу). Оптимизирован под **NVIDIA RTX 4060 (8 ГБ VRAM)**, но работает на любом железе с подстройкой INI.

## Состав комплекта

| Файл | Назначение |
|---|---|
| `llama-windows-install.ini` | Единый конфиг (пути, сеть, версия, параметры llama-server) |
| `llama-windows-install.ps1` | Установка, обновление, переустановка, скачивание моделей, диагностика |
| `llama-windows-uninstall.ps1` | Удаление службы, очистка брандмауэра, PATH и переменных окружения |
| `README.md` | Этот файл (документация) |

Все четыре файла должны лежать в одной папке — например, `D:\AI\Llama.cpp\Install`.

---

## 1. Ключевые возможности

1. **Режим Router.** `llama-server` запускается без `--model`, но с `--models-dir` и `--models-max 1`. Модели подгружаются в память по запросу и выгружаются при смене модели (не более 1 одновременно), что критично для 8 ГБ VRAM.
2. **Автоматическое скачивание моделей.** Скрипт умеет скачивать `.gguf` с Hugging Face с текстовым прогресс-баром. Если отложить скачивание, Router сделает это сам при первом запросе.
3. **Безопасное обновление.** Все пользовательские данные (модели, кэш, логи, конфиги API) защищены от удаления и не попадают в бэкап. Бэкапятся и заменяются только бинарники (`llama-server.exe`, `*.dll`).
4. **Проверка зависимостей.** Скрипт проверяет наличие Visual C++ Redistributable, совместимость версии CUDA (парсит `nvidia-smi`, включая новый формат `CUDA UMD Version:`) и объём VRAM.
5. **Диагностика при сбоях.** Если служба не стартует, скрипт автоматически пробует запустить `llama-server.exe` напрямую с `--verbose` и в режиме CPU (`-ngl 0`), после чего выводит причину.

## 2. Полное описание `llama-windows-install.ini`

### Секция `[paths]` — Пути и каталоги

| Параметр | По умолчанию | Описание |
|---|---|---|
| `LlamaCppDir` | `D:\AI\Llama.cpp` | Корневой каталог установки бинарников. Здесь лежит `llama-server.exe`. |
| `ModelsDir` | `<LlamaCppDir>\Models` | Каталог для файлов моделей `.gguf`. Защищён от удаления. |
| `CacheDir` | `<LlamaCppDir>\Cache` | Каталог кэша Router (метаданные, временные файлы llama.cpp). Защищён от удаления. |
| `NssmDir` | `C:\Program Files\NSSM` | Каталог для распаковки утилиты NSSM. |
| `LogsDir` | `<LlamaCppDir>\logs` | Каталог для логов службы (`llama-server.out.log`, `llama-server.err.log`). Защищён. |
| `DownloadsDir` | `<LlamaCppDir>\Downloads` | Кэш скачанных архивов (zip с бинарниками и NSSM). Защищён. |
| `BackupDir` | `<LlamaCppDir>\Backup` | Каталог для резервных копий бинарников при обновлении. Защищён. |

> **Примечание:** Если оставить поля пустыми, скрипт автоматически подставит пути относительно `LlamaCppDir`.

### Секция `[service]` — Настройки службы Windows

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ServiceName` | `LlamaCpp` | Имя службы в диспетчере задач Windows. |
| `StartType` | `SERVICE_DELAYED_AUTO_START` | Тип запуска. Варианты: `SERVICE_DELAYED_AUTO_START`, `SERVICE_AUTO_START`, `SERVICE_DEMAND_START`. |
| `StartTimeoutSeconds` | `180` | Сколько секунд ждать запуска службы (большие модели грузятся долго). |
| `AppRestartDelay` | `10000` | Задержка (в мс) перед перезапуском службы после падения (защита от циклов). |
| `AddToPath` | `true` | Добавить `LlamaCppDir` в системный `PATH`, чтобы `llama-server` был доступен из консоли. |
| `AddNssmToPath` | `true` | Добавить папки `win32` и `win64` NSSM в `PATH`, чтобы `nssm` был доступен из любой консоли. |
| `LogRetentionDays` | `7` | Ротация логов: удалять файлы в `LogsDir` старше N дней. `0` — отключить очистку. |

### Секция `[network]` — Сеть и брандмауэр

| Параметр | По умолчанию | Описание |
|---|---|---|
| `Host` | `0.0.0.0` | Адрес, на котором слушает сервер. `0.0.0.0` — доступ по сети, `127.0.0.1` — только локально. |
| `Port` | `9931` | TCP-порт для HTTP API и Web UI. |
| `FirewallEnabled` | `true` | Создавать ли правило в Windows Firewall для входящих подключений. |
| `FirewallSubnet` | `192.168.117.0/24` | Подсеть (CIDR), которой разрешён доступ. Пусто — правило не создаётся. |

### Секция `[downloads]` — Загрузка бинарников

| Параметр | По умолчанию | Описание |
|---|---|---|
| `LlamaCppVersion` | `ask` | Версия для установки. `ask` — показать меню, `latest` — последняя, `b12184` — конкретная. |
| `NssmUrl` | GitHub URL | Прямая ссылка на архив NSSM. |
| `KeepDownloads` | `true` | Хранить ли скачанные zip-архивы в `DownloadsDir` (полезно для переустановки). |

### Секция `[server]` — Параметры `llama-server`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `CtxSize` | `4096` | Размер контекста (`--ctx-size`). Больше контекст — больше VRAM. |
| `NGpuLayers` | `999` | Количество слоёв на GPU (`-ngl`). `999` — все слои. Для 7B на 8 ГБ VRAM обычно `28-33`. |
| `FlashAttention` | `true` | Включает `-fa on` (Flash Attention). Снижает расход KV-кэша. **В новых версиях llama.cpp требует явного значения `on`**. |
| `Parallel` | `1` | Количество параллельных слотов (`--parallel`). |
| `ExtraArgs` | *(пусто)* | Дополнительные аргументы, которые будут добавлены в командную строку как есть. Пример: `--threads 8 --batch-size 512`. |
| `ForceCPU` | `false` | Принудительно запустить без GPU (`-ngl 0`). Для диагностики или работы на слабых машинах. |

### Секция `[models]` — Управление моделями

| Параметр | По умолчанию | Описание |
|---|---|---|
| `Interactive` | `true` | Показывать интерактивное меню выбора моделей при установке. |
| `PreDownload` | `true` | Скачивать модели сразу при установке (с прогресс-баром). Если `false` — Router скачает их при первом запросе. |
| `Models` | *(пусто)* | Список моделей для неинтерактивного режима (через запятую). Имена из меню: `qwen7b`, `llama8b`, `coder7b`, `gemma2b`, `deepseek8b`. |

## 3. Логика обновления и резервного копирования

При обновлении или переустановке скрипт действует по следующему алгоритму:

1. **Останавливает службу** и завершает процессы `llama-server`.
2. **Создаёт бэкап** в `BackupDir\LlamaCpp_<дата_время>`.
   - **Копируются только бинарники** (`llama-server.exe`, `llama.dll`, `ggml*.dll`, `cudart*` и т.п.).
   - **Не копируются** (и не удаляются) защищённые объекты:
     - `Install\`
     - `logs\`
     - `Downloads\`
     - `Backup\`
     - `Models\`
     - `Cache\`
     - `api-keys.txt`
     - `api-keys.json`
3. **Удаляет старые бинарники** из корня `LlamaCppDir` (кроме защищённых папок и файлов).
4. **Скачивает и распаковывает новую версию**.
5. **Пересоздаёт службу** с новыми аргументами.

> **Важно:** Файлы `api-keys.txt` и `api-keys.json` (если вы используете аутентификацию клиентов) **не удаляются и не бэкапятся**. Они остаются на своих местах нетронутыми, чтобы не сломать доступ к API.

## 4. Параметры запуска

### `llama-windows-install.ps1`

| Параметр | Описание |
|---|---|
| `-Force` | Не задавать интерактивных вопросов (не показывать меню версий, брать `LlamaCppVersion` из INI, не спрашивать про переустановку и модели). |
| `-ForceDownload` | Принудительно перекачать архивы и сбросить кэш списка релизов. |
| `-Upgrade` | Режим автообновления: включает `-Force`, ставит `LlamaCppVersion=latest`, отключает интерактивный выбор моделей. |
| `-NoPause` | Не ждать нажатия Enter в конце (для Планировщика и CI/CD). |
| `-ConfigPath` | Путь к нестандартному INI-файлу. |

### `llama-windows-uninstall.ps1`

| Флаг | Что удаляет |
|---|---|
| `-PurgeModels` | `ModelsDir` (скачанные `.gguf`) |
| `-PurgeLlamaCpp` | Бинарники в `LlamaCppDir` (папки `Install`, `logs`, `Downloads`, `Backup`, `Models`, `Cache` и файлы `api-keys.*` сохраняются) |
| `-PurgeLogs` | `LogsDir` |
| `-PurgeDownloads` | `DownloadsDir` (включая подпапки версий) |
| `-PurgeBackup` | `BackupDir` |
| `-Force` | Не задавать вопросов (удалять без подтверждения) |
| `-NoPause` | Не ждать Enter в конце |

> Без флагов удаляется только служба, правило брандмауэра, записи в `PATH` и переменные окружения. Все каталоги остаются на месте.

## 5. Быстрый старт

1. Отредактируйте `llama-windows-install.ini`:
   - Проверьте `FirewallSubnet`.
   - Подстройте `CtxSize` и `NGpuLayers` под вашу видеокарту.
2. Запустите `.\llama-windows-install.ps1`.
3. Выберите версию `llama.cpp` (Enter — последняя).
4. Выберите модели для скачивания (или пропустите — Router скачает их при первом запросе).
5. Дождитесь проверки `/health` и завершения установки.

---

## 6. Автообновление (Планировщик Windows)

1. Откройте **Планировщик заданий**.
2. Создайте задачу с триггером (например, ежедневно в 3:00).
3. В действии укажите:
   - **Программа**: `powershell.exe`
   - **Аргументы**: `-NoProfile -ExecutionPolicy Bypass -File "D:\AI\Llama.cpp\Install\llama-windows-install.ps1" -Upgrade -NoPause`
4. Включите опцию **«Выполнять с наивысшими правами»**.
5. Лог работы будет писаться в `D:\AI\Llama.cpp\Install\llama-windows-install.log`.

## 7. Проверка работы

```powershell
# Статус службы
Get-Service LlamaCpp

# Health-check (Router запущен, модели ещё не в памяти)
Invoke-RestMethod http://127.0.0.1:9931/health

# Список моделей, доступных Router'у
Invoke-RestMethod http://127.0.0.1:9931/v1/models

# Простой запрос к модели (первый запрос загрузит модель в память)
Invoke-RestMethod -Uri http://127.0.0.1:9931/v1/chat/completions -Method POST -ContentType 'application/json' -Body '{"model":"Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf","messages":[{"role":"user","content":"Hello"}]}'
